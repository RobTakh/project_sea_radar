# Checkpoint 03 — серверный reader AISStream и проверка без ключа

**Архив:** `sea-radar-checkpoint-03-<sha>.zip`, где sha — коммит, в который входит эта запись
**Дата:** 2026-09-18  **Задачи:** B-08…B-10

## Запуск

`npm install`
`npm run dev`
`curl http://localhost:3000/api/snapshot`
`npm run test:e2e`

## Что сделано

- В `.gitignore` правило `.env*` игнорирует `.env.local`; `.env.example` исключён из игнорирования.
- В `.claude/settings.json` добавлены запреты чтения `.env`, `.env.local` и `.env.*.local`; `.env.example` под эти запреты не попадает.
- Добавлен серверный модуль чтения `AISSTREAM_API_KEY` без вывода значения.
- Добавлен Route Handler `GET /api/snapshot` с `runtime = 'nodejs'`.
- Reader открывает WebSocket AISStream, после открытия отправляет подписку с районом из конфигурации и фильтром `PositionReport`.
- Reader возвращает первое сообщение без преобразования или `raw: null` после срока при успешно отправленной подписке.
- Срок reader составляет 15 секунд от начала обработки; предусмотрены инъецируемые источник сокета и часы для тестов.
- Для ошибок endpoint использует фиксированные коды и сообщения из задания; сырой текст ошибки и ключ в ответ не включаются.
- При завершении reader очищает таймер, снимает обработчики и закрывает соединение.
- Интерфейс, карта, демонстрационные маршруты и карточка судна в этом занятии не изменялись.

## Проверки

- `npx tsc --noEmit` → passed; проверка типов завершилась без ошибок.
- `npm run build` → passed; production-сборка Next.js завершилась успешно, маршрут `/api/snapshot` включён как динамический серверный маршрут.
- Запрос к `GET /api/snapshot` при явно пустом `AISSTREAM_API_KEY` → HTTP 502 с кодом `no_api_key` и сообщением «Ключ AISStream не настроен»; соединение в этом сценарии не открывалось.
- `npm run test:e2e` → passed 3; один worker проекта `chromium`.
- Автоматическими браузерными тестами проверены три демонстрационных маркера, открытие карточки выбранного судна и сохранение карточки после повторного клика.
- Отдельной автоматической проверки reader с fake socket, заготовленным сообщением и управляемыми часами не выполнялось.
- Отдельной проверки отсутствия ключа в production-клиентском bundle выполнен поиск по собранным файлам; совпадений в `.next/static` не найдено.
- Логи серверного кода не проверялись запуском с настоящим ключом; в изменённых серверных файлах вызовов логирования нет.
